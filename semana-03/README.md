# Semana 3 — Trabajo colaborativo en GitHub

Esta semana se practica un flujo de colaboración basado en ramas y Pull Requests.
La contribución de esta carpeta es una guía de revisión para mantener cambios
pequeños, claros y fáciles de integrar.

## Checklist para revisar un Pull Request

Antes de integrar un cambio, la persona revisora debe comprobar lo siguiente:

- El título y la descripción explican qué problema resuelve el cambio.
- La modificación está limitada al objetivo del Pull Request y no incluye archivos
  ajenos.
- La documentación conserva una estructura y un lenguaje consistentes con el
  repositorio.
- Los enlaces, rutas y comandos incluidos se pueden entender y usar.
- Las observaciones se dejan como comentarios claros y accionables antes de
  aprobar o integrar el cambio.

## Flujo aplicado

1. Crear una rama descriptiva para la modificación.
2. Realizar y confirmar el cambio con un commit.
3. Abrir un Pull Request hacia `main`.
4. Revisar el cambio mediante un comentario de revisión.
5. Integrar el Pull Request una vez comprobado el contenido.

Este flujo deja un historial visible de la contribución y facilita que futuras
personas colaboradoras entiendan qué se cambió y por qué.
